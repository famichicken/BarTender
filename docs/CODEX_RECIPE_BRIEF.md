# Codex 引き渡しブリーフ — レシピデータ＆画像生成

> このドキュメント単体で作業できるよう、必要な文脈・スキーマ・要件・受け入れ基準をまとめています。
> 全体設計は [`SPEC.md`](SPEC.md) を参照（特に §4.2 レシピ、§11〜§12 液面ガイド/ゆる版、§15 安全要件）。

## 0. ミッション
**EvenG2向けカクテルアプリ「BarTender」の内蔵レシピデータ（100種以上）と各レシピの画像を作成する。**
出力は本リポジトリのスキーマに準拠したJSONと画像アセット。アプリ本体（在庫判定・グラス表示・UI）は別途実装されるため、**Codexの担当はデータ＋画像のみ**。

## 1. アプリ文脈（最低限）
- 冷蔵庫・酒棚の在庫から「いま作れるカクテル」を判定し、スマートグラスEvenG2に手順を1ステップずつ表示するアプリ。
- レシピは **正式版（ml表記）** と **ゆる版（目分量・「〜風」・代用前提）** の二層。初心者でも「家にあるもので1杯」作れることを重視。
- 多言語: **日本語(ja) / 英語(en)**。`LocalizedText` は **en 必須**・ja 推奨。
- G2はモノクロ約10行の狭い画面。**手順の en は簡潔**に（1ステップ=1動作、目安20〜40字相当）。

## 2. 生成する成果物
```
data/
├─ ingredients.json     # Ingredient[]（材料カタログ）
└─ recipes.json         # Recipe[]（カクテル100種以上）
assets/
└─ recipes/<recipe_id>/
   ├─ hero.webp         # メイン画像（必須）
   ├─ thumb.webp        # 一覧サムネ（任意・hero縮小可）
   └─ glass.svg         # G2タイル向けグラスシルエット（任意・単色）
```
- スキーマ: [`schema/recipe.schema.json`](schema/recipe.schema.json) / [`schema/ingredient.schema.json`](schema/ingredient.schema.json)
- 形式見本: [`examples/sample-data.json`](examples/sample-data.json)（この形にそろえる）

## 3. レシピ要件

### 3.1 件数と配分（ユニーク100種以上）
ベース別に定番を割り振る。グループは重複可（例: ウイスキーサワー = `["whisky","sour"]`）が、**ユニークなレシピ数で100以上**。

| グループ(`groups`) | 目標数 | 定番例 |
|---|---|---|
| `gin` | 18〜 | ジントニック, マティーニ, ギムレット, ネグローニ, トムコリンズ, ホワイトレディ, ギブソン, シンガポールスリング |
| `rum` | 15〜 | モヒート, ダイキリ, ピニャコラーダ, マイタイ, ダークアンドストーミー, ラムコーク, XYZ |
| `whisky` | 15〜 | ハイボール, ウイスキーサワー, オールドファッションド, マンハッタン, ミントジュレップ, ラスティネイル, ゴッドファーザー |
| `vodka` | 15〜 | モスコミュール, ソルティドッグ, スクリュードライバー, ブラッディマリー, コスモポリタン, シーブリーズ |
| `sour` | 10〜 | ウイスキーサワー, アマレットサワー, ピスコサワー, ジンサワー |
| `beer` | 10〜 | シャンディガフ, レッドアイ, パナシェ, ブラックベルベット |
| `non_alcohol` | 17〜 | シャーリーテンプル, サラトガクーラー, シンデレラ, ノンアルモヒート, フルーツパンチ, 各種モクテル |

> 追加グループ候補（任意）: `tequila` / `brandy` / `wine_sparkling` / `liqueur`。

### 3.2 分類タグの付与
- `flavors`（味/感覚, 複数可）: `refreshing`(さわやか) / `mild` / `sweet` / `dry` / `bitter` / `fruity` / `sour_taste` / `rich` / `herbal` / `creamy`
- `strength`: `light`(〜10%) / `medium`(10〜20%) / `strong`(20%〜) ← `estimatedAbv` と整合させる
- `method`: `build` / `shake` / `stir` / `blend`
- `tags`（おすすめ分類, 任意）: `aperitif`/`digestif`/`party`/`relax`/`nightcap` ・ `spring`/`summer`/`autumn`/`winter` ・ `easy`/`intermediate` ・ `classic`/`signature`

### 3.3 正式版 手順（`steps`）
- 1ステップ=1動作。en は簡潔（命令形）。ja併記。
- 分量は `ingredients[].amount/unit` に持たせ、手順文に過度な数値を詰め込まない。

### 3.4 ゆる版（`casual`）
- `modeAdjustable: true` のレシピには `casual` を付与（少なくとも主要50種は推奨）。
- `casual.name`: 「〜風」名称。`casual.maxIngredients`: 3前後。
- `casual.visualSteps`: 液面ガイドの**色規約**に沿った視覚的手順 →
  **赤=ベース酒 / 黄=酸味（レモン・シロップ少量）/ 青=割材（炭酸）/ 灰=氷**。例:「ジンを赤線まで」「炭酸を青線まで」。
- `casual.substitutions`: 代用候補（例: `lime`→`lemon`/`lemon_juice`）。"足りなくても作れる"印象を作る。

### 3.5 推定アルコール度数（`estimatedAbv`）
- 材料と分量からおおよそのABV(%)を算出（ノンアルは0）。安全注意表示に使うため**過小評価しない**。

## 4. 材料カタログ（`ingredients.json`）要件
- レシピが参照する全 `ingredientId` を網羅。`id` は小文字スネークケース（例: `lime_juice`）。
- `category`: `spirit`/`liqueur`/`mixer`/`fruit`/`bitters`/`garnish`/`other`。
- 常備品（`water`/`ice`/`sugar` 等）は `isStaple: true`。
- 代替関係は `substitutes`（例: `lime.substitutes = ["lemon"]`）。`aliases` に ja/en の別名・表記ゆれ（「ポッカレモン」等）。
- バーコード(`barcodes`)は任意（空でよい）。

## 5. 画像要件（バーの世界観で統一）
アプリのUIは「大人のバー／スピークイージー」のダーク基調（琥珀・ゴールドのアクセント）。画像も**全レシピで一貫したトーン**に。

- **被写体**: 完成したカクテルを、そのレシピに合う適切なグラスで。背景は暗めのバーカウンター/間接照明、控えめなボケ。
- **トーン**: ダーク&ムーディ、温かみのある光、上質感。ガーニッシュは正確に（例: ジントニックにライム）。
- **構図**: 中央〜やや上、グラス全体が入る。`hero` は正方形 **1024×1024**（または 4:5）。`thumb` は 600×600 程度。
- **形式**: `webp`（高品質）。`glass.svg` はG2タイル用の**単色・簡素なグラスシルエット**（モノクロ表示前提）。
- **文字なし**: 画像内にテキスト・ロゴ・透かしを入れない。
- **命名**: `assets/recipes/<recipe_id>/hero.webp` のように `recipe_id` 配下に配置し、`recipes.json` の `image` で相対参照。
- **一貫性**: 同一の照明・彩度・背景方針をシリーズで統一（プロンプト/シードを固定推奨）。
- **安全**: 人物（特に未成年）を主体にしない。飲酒を煽る演出（一気飲み等）は避ける。

## 6. コンテンツ安全・法務（必須遵守 / SPEC §15）
- 未成年飲酒・飲酒運転を想起させる表現を入れない。
- 「一気飲み」「大量飲酒」「酔うことの目的化」を促す表現・画像を避ける。
- 各レシピに `estimatedAbv` を必ず設定（注意表示に使用）。`non_alcohol` は度数0で**低アル/ノンアルの選択肢を充実**させる。
- レシピ名・説明は中立的・実用的に（過度に煽情的にしない）。

## 7. 受け入れ基準（チェックリスト）
- [ ] `recipes.json` がユニーク **100件以上**、§3.1の配分を概ね満たす
- [ ] 全レシピが `recipe.schema.json` に**バリデーション通過**（`additionalProperties:false` に注意）
- [ ] 全 `ingredientId` が `ingredients.json` に存在（参照整合性）
- [ ] 全 `name`/`steps` に **en あり**、ja も基本付与
- [ ] `groups`/`flavors`/`strength`/`method` が定義語彙の範囲内
- [ ] `estimatedAbv` と `strength` が整合
- [ ] 主要レシピに `casual`（ゆる版・色規約準拠の visualSteps）あり
- [ ] 各レシピに `hero` 画像があり、トーンが統一、文字なし、正しいグラス/ガーニッシュ
- [ ] 安全要件（§6）に違反する表現・画像がない

## 8. 進め方の提案（任意）
1. まず `ingredients.json` を確定（代替関係・常備品を含む）。
2. グループごとに正式版レシピを起こし、`casual` を付与。
3. スキーマ検証 → 参照整合性チェック（`ingredientId`）。
4. 画像はシリーズで一貫プロンプトを使い、`recipe_id` 単位で生成・配置。
5. 最後に件数・配分・受け入れ基準を自己点検。

> 不明点や語彙追加が必要な場合（新しい材料カテゴリ・グラス種別など）は、スキーマの enum を拡張せず**既存語彙へのマッピングを優先**し、必要なら別途メモに列挙してください。
