# BarTender 設計仕様書（ドラフト v0.2 / Addendum v1.0 統合）

Even Realities **G2** スマートグラス向けカクテルアシスタント。
本書は実装着手前の合意形成を目的とした設計ドキュメントです。確定値ではなく、レビューで詰める前提の叩き台を含みます（🔶印 = 要確認・要検証）。

- 対象プラットフォーム: Even Realities G2 ＋ Even Hub（アプリストア）、R1 ファンクショナルリング
- 最終更新: 2026-06-06

---

## 1. 背景・狙い

カクテル作りは「家にある材料で何が作れるか分からない」「レシピを見ながらだと手が塞がる／スマホが汚れる」という2つの障壁がある。
BarTender は **在庫起点のレコメンド** と **グラス上のハンズフリー手順表示** でこの2点を解消する。

### ユーザー価値
- 買い足し不要で「今すぐ作れる」が分かる。
- シェイカーやボトルで両手が塞がっていても、視線の先（グラス）に次の手順が出る。
- お気に入り・季節特集・人気から次の一杯を発見できる。

## 2. プラットフォーム前提（G2 / Even Hub）

公式ドキュメント（hub.evenrealities.com）およびコミュニティSDK（even-toolkit）から把握した制約。実機/最新SDKで検証する 🔶。

| 項目 | 値・内容 |
|------|----------|
| ディスプレイ | 約 576×288px、モノクロ（グリーン）、テキスト**約10行** |
| 表示モード | テキスト/カラム、チャート、ホームのタイル（画像 最大288×144px） |
| 入力 | **R1リング**（タップ / ダブルタップ / スクロール）、**音声入力**（STT）、IMU（ヘッド/モーション） |
| 開発 | TypeScript + Vite（+ React のコンパニオンWeb）、Tailwind |
| ブリッジ | `EvenHubBridge`（IMU・オーディオ等のハードウェア制御）、`useGlasses` フック |
| UIビルダー | `buildScrollableList` / `buildScrollableContent`（スクロールインジケータ付き）、アクションバービルダー |
| 配布 | Even Hub |

### 重要な制約と方針
- **モノクロ・10行・狭幅** → グラス画面は「1画面1メッセージ」。1ステップを大きく＋進捗（例: `3/6`）の最小構成。装飾より可読性。
- **多言語フォント** 🔶 — グラス側フォントが各言語（日本語/中国語/韓国語等）のグリフをどこまで持つか未確定。対策として:
  - レシピデータは `LocalizedText`（`en` 必須）で多言語保持。詳細は §4.7。
  - 端末が選択言語を表示不可の場合は **en/ローマ字へフォールバック**（設定で切替）。
  - スマホ側は各言語フル対応（制約なし）。
- **オフライン耐性** — グラスは母艦（スマホ/ブリッジ）依存のため、判定済みデータをスマホからグラスへ渡す前提。コア機能はネット非依存で動くよう設計。

## 3. スコープと役割分担

### 3.1 構成（決定: スマホ在庫 ＋ グラスでレシピ）

```
┌─────────────────────────┐        ┌──────────────────────┐
│  スマホ コンパニオンWeb     │  BLE/  │   G2 グラス           │
│  (Vite+TS+React+Tailwind) │ bridge │  (even-toolkit)       │
│                           │ ─────▶ │                      │
│  • 在庫の登録/編集          │        │  • 作れる一覧         │
│  • レシピ閲覧/検索          │        │  • レシピ手順表示      │
│  • Favorites              │        │  • R1リング/音声操作   │
│  • 発見/ピックアップ/LP     │        │                      │
│  • 判定エンジン実行         │        │                      │
└─────────────────────────┘        └──────────────────────┘
            │
            ▼ (任意)
   ┌──────────────────┐
   │ クラウド (Supabase) │  同期・公開LPデータ・自作レシピ共有
   └──────────────────┘
```

- **判定エンジンはスマホ側**で実行し、結果（作れる/あと1つ/代替）をグラスへ送る。グラスは表示と操作に専念。

### 3.2 スコープ外（現時点）
- 計量器/スマートスケール連携、決済、SNS共有（将来検討）。

## 4. 機能要件

### 4.1 在庫管理（スマホ）
- **手動チェックリスト**（Phase 1）: カテゴリ別（スピリッツ/リキュール/ミキサー/フルーツ/ビター/ガーニッシュ/その他）の材料リストを **トグル**。常備品（水/氷/砂糖等）は既定でON。
- **検索 / クイック追加**: 材料名・別名で絞り込み。
- **音声入力**（Phase 2）: 「ウォッカ追加」「トニック切らした」等で在庫を増減。
- **読み取り入力**（Phase 3 / 優先度: できれば）:
  - **バーコード（JAN）連続読み込み**（できれば対応） — カメラを向けるだけで複数本を連続スキャン。**二重読み込み防止**（直近スキャンのデバウンス＋セッション内 dedupe、同一コードはクールダウン中は無視、確定はトースト/カウントで可視化）。JAN網羅性の都合で難しい場合は下記にフォールバック。
  - **レシート読み取り（OCR）** — 購入レシートを撮影し、酒類の行をOCR＋AIで抽出して在庫へ一括反映。
  - **手動入力** — 上記が使えない/未対応環境での確実な手段（常に利用可能）。
  - 認識結果は material にマッピングして在庫へ反映（未知商品はユーザー確認の上で材料登録）。
- 在庫状態は **有（in）/ 残り少（low）/ 無し（out）** の **3段階**（確定）。`low` はレコメンドで「残り少」警告、補充候補として買い物リストに提案可能。

### 4.2 レシピ（内蔵 ＋ ユーザー追加）
- **内蔵キュレーションDB**: **定番カクテル 100種以上**。多言語（`LocalizedText`, ja/en）、グラス種別、技法、材料・分量、手順、分類タグ、ABV。オフライン同梱（JSON）。分類体系は §4.2.1。
- **ユーザー自作レシピ**（Phase 4）: 追加・編集・複製。内蔵DBと同スキーマ。`source: user`。
- レシピ詳細: 材料一覧（在庫の有無バッジ）、手順ステップ、グラス/技法、ABV、分類タグ、Favorites、「グラスへ送る」、不足材料の「買い物リストへ追加」。

#### 4.2.1 レシピ分類体系（タクソノミー）
複数の軸で横断的に絞り込み・ブラウズできるようにする。1レシピは複数の分類に属し得る（例: ウイスキーサワー = ベース:ウイスキー ＋ スタイル:サワー）。

- **ベース/主要グループ（`groups`, 複数可）** — トップのブラウズ単位。最低限カバー:
  - `gin`（ジン） / `rum`（ラム） / `whisky`（ウイスキー） / `vodka`（ウォッカ） / `sour`（サワー） / `beer`（ビール） / `non_alcohol`（ノンアルコール）
  - 追加候補 🔶: `tequila`（テキーラ） / `brandy`（ブランデー） / `wine_sparkling`（ワイン・スパークリング） / `liqueur`（リキュールベース）
- **味/感覚タグ（`flavors`, 複数可）** — 感覚的な分類:
  - `refreshing`（さわやか） / `mild`（マイルド） / `sweet`（甘口） / `dry`（辛口） / `bitter`（ビター） / `fruity`（フルーティ） / `sour_taste`（甘酸っぱい/サワー感） / `rich`（濃厚） / `herbal`（ハーバル/スパイシー） / `creamy`（クリーミー）
- **強さ（`strength`）**: `light`（弱め, 〜10% ABV目安） / `medium`（普通, 10〜20%） / `strong`（強め, 20%〜） — 分類はABVから自動付与＋手動補正 🔶
- **技法（`method`）**: build / shake / stir / blend（§5データモデル）。「作り方で分ける」軸として利用。
- **その他おすすめ分類（`tags`, 任意）**: TPO/シーン（`aperitif`食前 / `digestif`食後 / `party` / `relax` / `nightcap`）、季節（`spring`/`summer`/`autumn`/`winter`）、難易度（`easy`初心者向け / `intermediate`）、定番度（`classic`定番 / `signature`）。

#### 4.2.2 内蔵レシピの目標配分（100種以上 / 暫定 🔶）
各グループに定番をある程度割り振る。実数はレシピ作成時に調整。

| グループ | 目標数 | 定番例 |
|---------|-------|--------|
| ジン | 18〜 | ジントニック、マティーニ、ギムレット、ネグローニ、トムコリンズ、ホワイトレディ、ギブソン、シンガポールスリング |
| ラム | 15〜 | モヒート、ダイキリ、ピニャコラーダ、マイタイ、ダークアンドストーミー、ラムコーク、XYZ |
| ウイスキー | 15〜 | ハイボール、ウイスキーサワー、オールドファッションド、マンハッタン、ミントジュレップ、ラスティネイル、ゴッドファーザー |
| ウォッカ | 15〜 | モスコミュール、ソルティドッグ、スクリュードライバー、ブラッディマリー、ウォッカトニック、コスモポリタン、シーブリーズ |
| サワー | 10〜 | ウイスキーサワー、アマレットサワー、ピスコサワー、ジンサワー、各種サワー系 |
| ビール | 10〜 | シャンディガフ、レッドアイ、パナシェ、ブラックベルベット、ビアカクテル各種 |
| ノンアルコール | 17〜 | シャーリーテンプル、サラトガクーラー、シンデレラ、ノンアルモヒート、フルーツパンチ、各種モクテル |

> グループは重複計上あり（例: ウイスキーサワーはウイスキー＋サワー）。合計の **ユニーク種数で100以上** を担保。

### 4.2.3 買い物リスト & チェックリスト
- **登録**: 判定で不足した材料（`missing` / `low` / 代替不可分）を **ワンタップで買い物リストへ追加**。レシピ詳細・一覧・「あと1つ」提案の各所から追加可能。
- **チェックリスト**: 買い物リストは **チェック可能なリスト**。購入済みをチェック → 任意で在庫へ反映（チェック時に「在庫に追加しますか？」）。
- **自動提案**: `low`（残り少）材料や、Favoritesを作るのに不足している材料を補充候補として提案。
- **まとめ表示**: 「これを買えば +N 種のカクテルが作れる」を材料ごとに表示（買い物の動機付け）。複数レシピで共通して不足する材料を上位表示。
- **管理**: 手動追加・削除・並べ替え、カテゴリ別表示、共有（テキストエクスポート、将来クラウド共有）。

### 4.3 判定エンジン（作れる / あと1つ / 代替）
入力: 在庫（material集合）＋ レシピ集合。出力: 各レシピの判定ステータス。

- **必須材料** = `optional:false` かつ `garnish:false` の材料。ガーニッシュ/任意材料は判定から除外（不足は注記表示のみ）。
- ステータス:
  - `makeable`（作れる）: 必須材料がすべて在庫にある。
  - `makeable_with_substitute`（代替で作れる）: 不足必須材料に、在庫内の **代替候補**（material.substitutes）が存在。
  - `missing_one` / `missing_two`（あと1つ/2つ）: 代替適用後の不足が1〜2点。「○○があれば作れる」と提示（買い物動機）。
  - `unavailable`: 不足3点以上。
- 並び: makeable → with_substitute → missing_one → missing_two。
- 代替の扱い: 代替を使った場合はレシピ手順に「(代替: ジン→ウォッカ)」を明示。

### 4.4 グラス体験（R1リング ＋ 音声）
画面遷移（even-toolkit の screen単位 `{ display, action }`）:

```
Splash → MakeableList → RecipeOverview → Step(1..N) → Done
                 ▲                              │
                 └──────────── 一覧へ戻る ───────┘
```

- **MakeableList**: 作れるカクテルをスクロールリスト表示（`buildScrollableList`）。ステータスのアイコン/記号で区別。
- **RecipeOverview**: 名前・グラス・技法・材料サマリ（在庫前提なので「足りないものなし」想定）。
- **Step(i/N)**: 1ステップを大きく＋進捗。シェイク/ステア等の所要は文言で（自動タイマーはMVP対象外）。
- **操作マッピング**:

| 操作 | R1リング | 音声コマンド（例） |
|------|----------|-------------------|
| 次へ | タップ | 「次」「next」 |
| 戻る | ダブルタップ | 「戻る」「back」 |
| 一覧/リスト移動 | スクロール | 「一覧」「list」 |
| 完了 | （最終ステップでタップ） | 「完了」「done」 |
| 最初から | — | 「最初から」「restart」 |

- ジェスチャは debounce ＋ タップ後スクロール抑制（even-toolkit 準拠）。音声は誤認対策に短語彙＋確認なしの即時実行（破壊的操作なし）。

### 4.5 Favorites
- レシピを ★ 保存。スマホで一覧/管理、グラスの一覧にも「お気に入り」フィルタを用意。
- ローカル保存（ハイブリッド構成で任意クラウド同期）。

### 4.6 発見 / ピックアップ ＆ LP（公開 ＋ アプリ内 両方）
- **公開LP**（集客/Even Hub掲載用）: アプリ紹介・世界観・おすすめカクテル。SEO配慮。コンテンツは共通データから供給。
- **アプリ内ホーム/発見タブ**: 同じピックアップデータを内部表示。
- **ピックアップの内容**（すべて採用）:
  - **在庫連動推薦**: 「今の在庫で作れる」をパーソナライズ表示。
  - **編集・季節特集**: 季節/イベント/テーマのキュレーション（編集データ）。
  - **人気/ランキング**: 人気・定番・Favorites多順。
- 公開LPはパーソナライズ不可な範囲（季節特集・人気）を中心に、ログイン時のみ在庫連動を反映。

### 4.8 デザイン方針（バーの世界観でオシャレに）
スマホ（コンパニオン）と公開LPは「**大人のバー**」を思わせる、落ち着いた上質なトーンで統一する。

- **トーン&ムード**: 薄暗いバーカウンター、間接照明、琥珀色の酒。**ダークテーマ基調**（深いチャコール/ナイトブルー＋ウッド調）。
- **カラー**（暫定 🔶）:
  - 背景: 深いダーク（`#121012` 系の黒〜ダークブラウン）
  - アクセント: **琥珀/ゴールド**（`#C8A05A` 系）、差し色にボトルグリーン/バーガンディ
  - テキスト: オフホワイト＋ミュートしたグレー
- **タイポグラフィ**: 見出しに**セリフ/ディスプレイ体**（高級感）、本文はサンセリフで可読性確保。日本語は明朝×ゴシックの使い分け 🔶。
- **質感**: 微細なノイズ/グレイン、ガラスの反射、コースター/ラベル風のカード、ネオンサイン的なアクセントを控えめに。
- **モーション**: 注ぐ/満たす演出、リストのフェード、過度でない上品なトランジション。
- **アイコン/イラスト**: ラインアートのグラス・ボトル。カクテルごとにグラスシルエットで識別。
- **トーンの一貫性**: LP→アプリで世界観を連続させる（同じカラー/書体/写真トーン）。
- **アクセシビリティ**: ダーク基調でもコントラスト比 AA を確保。フォントサイズ可変。
- **グラス（G2）側は別物**: ハードウェアがモノクロ・グリーンのため装飾不可。こちらは「視認性最優先のミニマル」（§2）。世界観はスマホ/LPで表現し、グラスは機能に徹する、と役割を分離。

> 参考の方向性（ムードボードは別途）: スピークイージー風、ダーク&ラグジュアリー、Aesop/高級カクテルブックのような落ち着き。

### 4.9 ダッシュボード & 実績（nice-to-have / 後期フェーズ）
「マイバーの営業記録」として、**何を・いつ作ったか**を記録し、統計と実績で振り返り・継続の動機にする。マスト機能ではないが、世界観と相性が良くリテンション向上が期待できる。

- **作成ログ（History）**:
  - グラスで手順を「**完了**」した時点で1杯を自動記録（recipeId / 日時 / 使った代替 / グラス）。手動追加・削除も可。
  - メモ・評価（★）・写真添付（任意）を付けられる「テイスティングノート」。
  - タイムライン表示（日付別）。
- **ダッシュボード（統計）** — バーの世界観に沿ったビジュアルで:
  - 累計杯数、今月の杯数、連続記録（◯日連続/週）。
  - **よく作るカクテル** ランキング、**ベース別内訳**（ジン/ラム…の円グラフ）。
  - 時間帯・曜日の傾向、月別推移。使用材料ランキング、平均ABV。
  - 「制覇率」: 内蔵レシピ全体／各グループのうち作った割合（コレクション要素）。
- **実績 / バッジ（Achievements）** — ゲーミフィケーション:
  - 例: `first_pour`（初めての一杯）/ `ten_cocktails`（10杯）/ `all_bases`（全ベース制覇）/ `gin_master`（ジン10種）/ `weekend_bartender`（週末に作る）/ `seasonal_complete`（季節特集コンプ）/ `mixologist`（自作レシピ作成）/ `night_owl`（深夜の一杯）。
  - 解除時に控えめな演出（§4.8のモーション準拠）。獲得済み/未獲得を一覧表示（未獲得はヒント付き）。
- **保存/同期**: ローカル保存（ハイブリッドで任意クラウド同期）。プライバシーに配慮し、写真・ログはデフォルト端末内。
- **グラス連携**: 完了操作がそのまま記録トリガになるため、ハンズフリー体験と自然に統合（追加操作なしでログが貯まる）。
- **共有（任意・将来）**: 月次サマリやバッジをカード画像でエクスポート。

## 4.7 多言語対応（i18n）

アプリ全体を多言語対応にする。UI文言・レシピデータ・音声・認識辞書すべてをロケール対応にする。

- **対応言語（確定）**: **日本語(ja) / 英語(en) の2言語**。`en` を基準（フォールバック）言語とする。将来の言語追加に備え、型・辞書構造は任意ロケールに拡張可能な形（`LocalizedText`）を維持。
- **UI文言**: `packages/shared/i18n` にロケール別辞書（JSON, ja/en）を置き、`react-i18next` 等で切替 🔶。
- **レシピ/材料/ピックアップ**: 上記 `LocalizedText`（`en` 必須＋`ja`）で保持。未翻訳は `en` にフォールバックし、欠落を可視化（翻訳カバレッジ管理）。
- **言語切替**: 設定で手動選択（日本語/English）＋ 既定は端末ロケール自動判定。アプリ全体（スマホ/グラス）で共通の選択を反映。
- **フォーマット**: 数量・単位（ml/oz）、小数/分数表記。単位系（メートル法/USカスタマリ）も言語設定と別に切替可能にする 🔶。
- **グラス表示**: §2の通りフォントのグリフ対応が言語ごとに異なるため、日本語表示不可時は **en もしくはローマ字へフォールバック**。レシピデータが `en` を必ず持つことで担保。
- **音声・認識**: STTコマンド辞書と材料 `aliases` を ja/en で用意。レシート/バーコードの商品名出力も選択言語へ正規化。
- **ユーザー自作レシピ**: 入力は片方の言語だけでも可。`en` 未入力時は元言語を `en` キーにも複製し、フォールバックを成立させる。

## 5. データモデル（ドラフト）

共通型は `packages/shared` に定義（スマホ/グラス/クラウドで共有）。

```ts

// 現状の対応言語は ja / en。型は将来の言語追加に拡張可能。
type Locale = 'ja' | 'en' | (string & {});
type LocalizedText = { en: string } & Partial<Record<Locale, string>>;

// 材料
interface Ingredient {
  id: string;
  name: LocalizedText;
  category: 'spirit' | 'liqueur' | 'mixer' | 'fruit' | 'bitters' | 'garnish' | 'other';
  aliases?: string[];           // 別名・表記ゆれ（検索/音声/認識用）
  isStaple?: boolean;           // 常備品（既定ON: 水/氷/砂糖など）
  substitutes?: string[];       // 代替候補の ingredient id
  barcodes?: string[];          // JAN/EAN（バーコード認識用）
}

// 在庫（3段階・確定）
interface InventoryItem {
  ingredientId: string;
  level: 'in' | 'low' | 'out'; // 有 / 残り少 / 無し
  updatedAt: string;
}

// レシピ分類
type BaseGroup =
  | 'gin' | 'rum' | 'whisky' | 'vodka' | 'sour' | 'beer' | 'non_alcohol'
  | 'tequila' | 'brandy' | 'wine_sparkling' | 'liqueur';
type FlavorTag =
  | 'refreshing' | 'mild' | 'sweet' | 'dry' | 'bitter' | 'fruity'
  | 'sour_taste' | 'rich' | 'herbal' | 'creamy';
type Strength = 'light' | 'medium' | 'strong';

// レシピ（カクテル）
interface Recipe {
  id: string;
  name: LocalizedText;
  groups: BaseGroup[];          // ベース/主要グループ（複数可・ブラウズ単位）
  flavors?: FlavorTag[];        // 味/感覚タグ（さわやか・マイルド等）
  strength?: Strength;          // 強さ（ABVから自動付与＋手動補正）
  glass: 'rocks' | 'highball' | 'cocktail' | 'collins' | 'shot' | 'wine' | string;
  method: 'build' | 'shake' | 'stir' | 'blend';
  ingredients: RecipeIngredient[];
  steps: LocalizedText[];
  tags?: string[];
  abv?: number;
  image?: string;
  source: 'builtin' | 'user';
}
interface RecipeIngredient {
  ingredientId: string;
  amount?: number; unit?: string; // 例: 45, 'ml'
  optional?: boolean;             // 任意（判定除外）
  garnish?: boolean;              // ガーニッシュ（判定除外）
}

// 判定結果
type MatchStatus =
  | 'makeable' | 'makeable_with_substitute'
  | 'missing_one' | 'missing_two' | 'unavailable';
interface MatchResult {
  recipe: Recipe;
  status: MatchStatus;
  missing: string[];                              // 不足 ingredient id
  substitutions: { required: string; used: string }[]; // 適用した代替
}

// Favorites / ピックアップ
interface Favorite { recipeId: string; addedAt: string; }
interface Pickup { id: string; type: 'inventory' | 'seasonal' | 'popular'; title: LocalizedText; recipeIds: string[]; }

// 買い物リスト（チェックリスト）
interface ShoppingItem {
  ingredientId: string;
  checked: boolean;                 // 購入済みチェック
  source: 'auto' | 'manual';        // 不足判定からの自動追加 or 手動追加
  forRecipeIds?: string[];          // どのレシピのために必要か（"+N種作れる" 表示用）
  addedAt: string;
}

// 作成ログ（ダッシュボード/実績の元データ・nice-to-have）
interface MadeLog {
  id: string;
  recipeId: string;
  madeAt: string;                   // 作成日時（グラスの「完了」or 手動）
  source: 'glass' | 'manual';
  substitutions?: { required: string; used: string }[];
  rating?: number;                  // ★1〜5（任意）
  note?: string;                    // テイスティングノート（任意）
  photo?: string;                   // 写真（任意・端末内）
}

// 実績/バッジ
interface Achievement {
  id: string;                       // 例: 'first_pour' | 'all_bases' | 'gin_master'
  title: LocalizedText;
  description: LocalizedText;
  unlockedAt?: string;              // 未獲得は undefined
  progress?: { current: number; target: number }; // 進捗バー用
}
```

## 10. コンセプト拡張と整合方針

- **コンセプト拡張**: 「正確に作る趣味」→「**家にあるもので気軽に1杯**」。初心者の離脱要因（分量が分からない/材料がない/道具がない/作業中スマホを触りにくい/投稿しづらい）をAI＋グラス表示で解消。
- **Part Iとの整合**: 既存の在庫起点・判定エンジン・グラス手順・買い物リスト・ピックアップ・ダッシュボードは**土台として維持**し、その上にAI機能を重ねる。バーの世界観（§4.8）は維持しつつ「**ゆる版/カジュアルモード**」を併設して初心者にも開く。
- **アーキ整合（重要）**: AI（LLM/Vision）・SNSはバックエンド/通信/コスト前提。Part Iの「オフライン優先・ローカル純関数の判定エンジン」を**基盤として残し**、AIは**オンライン拡張**として上乗せ（ネット不可時はローカルの確定的提案・ゆる版固定ラインにグレースフルデグレード）。
- **正式版 / ゆる版の二層**: レシピは正式（ml表記）とゆる版（視覚/比率/代用/濃さ）を切替可能にする（§12）。

## 11. AI液面ガイド（AI-11）/ 透明シェイカー補助（AI-12）

現行EvenG2は**カメラなし前提**のため、**スマホ撮影画像**でガイドを生成し、G2には短文ナビを送る。将来のカメラ付きグラスでリアルタイムAR化（§16）。

### 11.1 グラス写真ベース液面ガイド
ユーザーがスマホでグラスを正面撮影 → AIがグラス形状・容量帯を推定 → 選択レシピ＋濃さ＋氷設定に応じた**投入ライン画像**を生成。

- **入力**: グラス写真 / レシピ / 濃さ（軽め・標準・濃いめ）/ 氷（あり・なし・多め）
- **出力**: ガイド画像、ライン情報（ベース酒/酸味/割材/最終ライン）、注意コメント（氷量・炭酸入れすぎ・推定精度）
- **ライン色規約**: 赤=ベース酒 / 黄=酸味（レモン・シロップ少量）/ 青=割材（炭酸）/ 灰帯=氷の目安
- **精度**: 厳密計量でなく**実用目安**。低信頼時は「ざっくりガイド」と明記、特殊グラスは手動選択/再撮影を案内。
- **G2連携表示例**: `1/4 氷を6割入れる` → `2/4 ジンを赤線まで` → `3/4 炭酸を青線まで` → `4/4 軽く1回混ぜる`
- **副次価値**: 完成イメージを投稿画像に流用可能。自宅グラスに合わせた「自分ごと」体験。

### 11.2 実装方針
- Vision対応LLM（例: Claude Vision）をEdge Function経由で呼び出し、グラス輪郭/高さ/容量帯を推定 → レシピのml配分を**相対液面（0〜1）**に変換 → クライアントで写真にオーバーレイ描画（Canvas/SVG）。
- 推定はサーバ、描画はクライアント（再描画・濃さ切替を即時反映）。`glass_profile`/`glass_guide_result` に保存（§13）。
- プライバシー: 画像のクラウド送信に**明示同意**、保存はデフォルト端末内・サーバは一時処理。

### 11.3 透明シェイカー補助（AI-12）
- 透明/目盛り付きシェイカーを「**あると便利**」枠の初心者向け推奨道具として登録（`tool_profile`）。必須ではない。
- 目盛り・高さ比率に合わせて投入ラインを表示。G2では「赤線まで」「目盛り100mlまで」など短文。
- シェイク後の泡立ち/氷で液面が変わるため**目安扱い**。金属シェイカー/グラス直作りでも成立する設計を維持。

## 12. ゆる版レシピ仕様

正式版（ml）に加え、**位置・比率・代用・濃さ**で作れる初心者向け表現を併設。

- **表示**: 「ジンリッキー風」等の"〜風"を許可。分量は「グラスの1/4」「底から1.5cm」「赤線まで」など視覚表現。
- **濃さモード**: **軽め / 標準 / 濃いめ** の3段階（味・度数に反映、液面ガイドにも連動）。
- **代用を最初から提示**: 「ライム→レモン/ポッカレモンでも可」。"足りなくても作れる"印象を作る。
- **初心者優先**: 材料3つ以内・工程3〜5以内を優先表示。道具は「なくても可」を明記。
- データ的には `Recipe.casual`（ゆる版表現）と `Recipe.modeAdjustable` を追加（§13）。正式/ゆるはUIトグルで切替（§8スマホ画面）。

## 13. AI味調整（AI-03）/ 好み学習（AI-09）

- **テイスティングレビュー**: 作成後に甘味/酸味/強さ/苦味を記録（`taste_review`）。→ AIが**次回配合**を提案（「前回より甘さ控えめ」等）。Part I の `MadeLog.rating/note` と統合（味の5軸を拡張）。
- **好み学習**: 評価履歴から味の傾向を学習し、提案（AI-01/AI-10）に反映。学習はローカル集計＋任意でサーバ。
- **アレンジ即時操作**: グラス音声「甘めにしたい」「弱めにしたい」で、その場で配合/濃さモードを切替。

## 14. SNS / コミュニティ（AI-06）

> ⚠️ 大きなスコープ拡張。アカウント・モデレーション・法務が伴う。MVP外（後期フェーズ）扱いを推奨。

- **AI投稿文生成**: 作成結果（レシピ/代用/失敗）からSNS投稿文を生成。X=短文 / Instagram=雰囲気重視 などトーン選択。代用や失敗を**ポジティブ**に表現。
- **コミュニティ設計**: ゆる投稿・代用例・**失敗歓迎**・「真似した」ボタン・「みんなの今日の一杯」。
- **必須の抑制設計**: 飲酒量を競わせない／一気飲み・大量飲酒・酔うこと目的化の投稿を抑制（§15）。
- 公開範囲（visibility）・通報/モデレーションを `post` に内包。

## 15. 安全・法務・コミュニティ要件（必須）

お酒を扱うアプリとして**必須**。MVPでも年齢確認とABV注意は実装する。

- **年齢確認**: 起動/オンボーディングで実施、未成年利用を禁止。
- **飲酒運転防止**: 注意表示を設ける。
- **ABV表示/注意（AI-08 飲みすぎ防止）**: 強いレシピに推定アルコール度数・注意を表示。杯数・度数に応じた**控えめな**注意（説教感を出さない短文）。
- **過度飲酒の不助長**: 「一気飲み」「大量飲酒」「酔うこと目的化」を煽らない。SNSで飲酒量を競わせない。
- **低アル/ノンアル導線**: 常に低アル・ノンアル提案への導線を用意（既存ノンアルグループと連動）。
- **AIプロンプト側の安全制約**: 未成年飲酒・飲酒運転につながる表現を出さない、強い酒/飲みすぎを促進しない（§17）。
- **プライバシー**: 写真/レシート/位置はデフォルト端末内、クラウド送信は明示同意。カメラ付きグラス拡張時は周囲のプライバシー配慮を仕様化。

## 17. AIプロンプト方針

- **レシピ提案**: 手持ち材料/好み/作業可能時間/杯数から初心者向けを提案。材料少・代用可・短工程を優先、"〜風"許可。強い酒/飲みすぎを促進せず、未成年飲酒・飲酒運転表現を排除。
- **液面ガイド生成**: 写真から輪郭・高さ・容量帯を推定しml→相対液面に変換。厳密でなく実用目安、3モード対応、低信頼は「ざっくりガイド」明記、特殊グラスは手動/再撮影案内。
- **投稿文生成**: 代用・失敗をポジティブに、飲酒を過度に煽らない、媒体別トーン、初心者が投稿しやすい文体。
- 実装: プロンプトとガードレールは `packages/shared/ai/prompts` に集約しテスト可能に。出力は型バリデーション（zod 等）で安全に取り込む。
