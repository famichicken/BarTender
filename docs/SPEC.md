# BarTender 設計仕様書（ドラフト v0.1）

Even Realities **G2** スマートグラス向けカクテルアシスタント。
本書は実装着手前の合意形成を目的とした設計ドキュメントです。確定値ではなく、レビューで詰める前提の叩き台を含みます（🔶印 = 要確認・要検証）。

- 対象プラットフォーム: Even Realities G2 ＋ Even Hub（アプリストア）、R1 ファンクショナルリング
- 最終更新: 2026-06-06

---

## 1. 背景・狙い

カクテル作りは「家にある材料で何が作れるか分からない」「レシピを見ながらだと手が塞がる／スマホが汚れる」という2つの障壁がある。
BarTender は **在庫起点のレコメンド** と **グラス上のハンズフリー手順表示** でこの2点を解消する。

### ユーザー価値
- 買い足し不要で「今すぐ作れる」が分かる。
- シェイカーやボトルで両手が塞がっていても、視線の先（グラス）に次の手順が出る。
- お気に入り・季節特集・人気から次の一杯を発見できる。

## 2. プラットフォーム前提（G2 / Even Hub）

公式ドキュメント（hub.evenrealities.com）およびコミュニティSDK（even-toolkit）から把握した制約。実機/最新SDKで検証する 🔶。

| 項目 | 値・内容 |
|------|----------|
| ディスプレイ | 約 576×288px、モノクロ（グリーン）、テキスト**約10行** |
| 表示モード | テキスト/カラム、チャート、ホームのタイル（画像 最大288×144px） |
| 入力 | **R1リング**（タップ / ダブルタップ / スクロール）、**音声入力**（STT）、IMU（ヘッド/モーション） |
| 開発 | TypeScript + Vite（+ React のコンパニオンWeb）、Tailwind |
| ブリッジ | `EvenHubBridge`（IMU・オーディオ等のハードウェア制御）、`useGlasses` フック |
| UIビルダー | `buildScrollableList` / `buildScrollableContent`（スクロールインジケータ付き）、アクションバービルダー |
| 配布 | Even Hub |

### 重要な制約と方針
- **モノクロ・10行・狭幅** → グラス画面は「1画面1メッセージ」。1ステップを大きく＋進捗（例: `3/6`）の最小構成。装飾より可読性。
- **多言語フォント** 🔶 — グラス側フォントが各言語（日本語/中国語/韓国語等）のグリフをどこまで持つか未確定。対策として:
  - レシピデータは `LocalizedText`（`en` 必須）で多言語保持。詳細は §4.7。
  - 端末が選択言語を表示不可の場合は **en/ローマ字へフォールバック**（設定で切替）。
  - スマホ側は各言語フル対応（制約なし）。
- **オフライン耐性** — グラスは母艦（スマホ/ブリッジ）依存のため、判定済みデータをスマホからグラスへ渡す前提。コア機能はネット非依存で動くよう設計。

## 4. 機能要件

### 4.1 在庫管理（スマホ）
- **手動チェックリスト**（Phase 1）: カテゴリ別（スピリッツ/リキュール/ミキサー/フルーツ/ビター/ガーニッシュ/その他）の材料リストを **トグル**。常備品（水/氷/砂糖等）は既定でON。
- **検索 / クイック追加**: 材料名・別名で絞り込み。
- **音声入力**（Phase 2）: 「ウォッカ追加」「トニック切らした」等で在庫を増減。
- **バーコード/写真認識**（Phase 3）:
  - **バーコード（JAN）連続読み込み** — カメラを向けるだけで複数本を連続スキャン。**二重読み込み防止**（直近スキャンのデバウンス＋セッション内 dedupe、同一コードはクールダウン中は無視、確定はトースト/カウントで可視化）。
  - 読めない場合は **写真AI（Claude Vision 等）** にフォールバックして銘柄/酒種を推定。
  - 認識結果は material にマッピングして在庫へ反映（未知商品はユーザー確認の上で材料登録）。
- 在庫状態は **有 / 残り少 / 無し** の3段階を持てる（残り少はレコメンドで警告表示）🔶（MVPは有/無の2値でも可）。

### 4.2 レシピ（内蔵 ＋ ユーザー追加）
- **内蔵キュレーションDB**: 定番カクテル数十〜100種。多言語（`LocalizedText`, `en`必須）、グラス種別、技法、材料・分量、手順、タグ、ABV。オフライン同梱（JSON）。
- **ユーザー自作レシピ**（Phase 4）: 追加・編集・複製。内蔵DBと同スキーマ。`source: user`。
- レシピ詳細: 材料一覧（在庫の有無バッジ）、手順ステップ、グラス/技法、ABV、Favorites、「グラスへ送る」。

### 4.3 判定エンジン（作れる / あと1つ / 代替）
入力: 在庫（material集合）＋ レシピ集合。出力: 各レシピの判定ステータス。

- **必須材料** = `optional:false` かつ `garnish:false` の材料。ガーニッシュ/任意材料は判定から除外（不足は注記表示のみ）。
- ステータス:
  - `makeable`（作れる）: 必須材料がすべて在庫にある。
  - `makeable_with_substitute`（代替で作れる）: 不足必須材料に、在庫内の **代替候補**（material.substitutes）が存在。
  - `missing_one` / `missing_two`（あと1つ/2つ）: 代替適用後の不足が1〜2点。「○○があれば作れる」と提示（買い物動機）。
  - `unavailable`: 不足3点以上。
- 並び: makeable → with_substitute → missing_one → missing_two。
- 代替の扱い: 代替を使った場合はレシピ手順に「(代替: ジン→ウォッカ)」を明示。

### 4.4 グラス体験（R1リング ＋ 音声）
画面遷移（even-toolkit の screen単位 `{ display, action }`）:

```
Splash → MakeableList → RecipeOverview → Step(1..N) → Done
                 ▲                              │
                 └──────────── 一覧へ戻る ───────┘
```

- **MakeableList**: 作れるカクテルをスクロールリスト表示（`buildScrollableList`）。ステータスのアイコン/記号で区別。
- **RecipeOverview**: 名前・グラス・技法・材料サマリ（在庫前提なので「足りないものなし」想定）。
- **Step(i/N)**: 1ステップを大きく＋進捗。シェイク/ステア等の所要は文言で（自動タイマーはMVP対象外）。
- **操作マッピング**:

| 操作 | R1リング | 音声コマンド（例） |
|------|----------|-------------------|
| 次へ | タップ | 「次」「next」 |
| 戻る | ダブルタップ | 「戻る」「back」 |
| 一覧/リスト移動 | スクロール | 「一覧」「list」 |
| 完了 | （最終ステップでタップ） | 「完了」「done」 |
| 最初から | — | 「最初から」「restart」 |

- ジェスチャは debounce ＋ タップ後スクロール抑制（even-toolkit 準拠）。音声は誤認対策に短語彙＋確認なしの即時実行（破壊的操作なし）。

### 4.5 Favorites
- レシピを ★ 保存。スマホで一覧/管理、グラスの一覧にも「お気に入り」フィルタを用意。
- ローカル保存（ハイブリッド構成で任意クラウド同期）。

### 4.6 発見 / ピックアップ ＆ LP（公開 ＋ アプリ内 両方）
- **公開LP**（集客/Even Hub掲載用）: アプリ紹介・世界観・おすすめカクテル。SEO配慮。コンテンツは共通データから供給。
- **アプリ内ホーム/発見タブ**: 同じピックアップデータを内部表示。
- **ピックアップの内容**（すべて採用）:
  - **在庫連動推薦**: 「今の在庫で作れる」をパーソナライズ表示。
  - **編集・季節特集**: 季節/イベント/テーマのキュレーション（編集データ）。
  - **人気/ランキング**: 人気・定番・Favorites多順。
- 公開LPはパーソナライズ不可な範囲（季節特集・人気）を中心に、ログイン時のみ在庫連動を反映。

## 4.7 多言語対応（i18n）

アプリ全体を複数言語に対応させる。UI文言・レシピデータ・音声・認識辞書すべてをロケール対応にする。

- **対応言語**（初期案 🔶）: 日本語(ja) / 英語(en) を一次対応、中国語(zh) / 韓国語(ko) / スペイン語(es) / フランス語(fr) を順次追加。`en` を基準（フォールバック）言語とする。
- **UI文言**: `packages/shared/i18n` にロケール別辞書（JSON）を置き、`react-i18next` 等で切替 🔶。
- **レシピ/材料/ピックアップ**: 上記 `LocalizedText`（ロケール→文字列, `en` 必須）で保持。未翻訳ロケールは `en`→既定言語の順でフォールバックし、欠落を可視化（翻訳カバレッジ管理）。
- **言語切替**: 設定で手動選択 ＋ 既定は端末ロケール自動判定。アプリ全体（スマホ/グラス）で共通の選択を反映。
- **書字方向/フォーマット**: 数量・単位（ml/oz）、小数/分数表記、将来のRTL言語に備え文字列はハードコードしない。単位系（メートル法/USカスタマリ）も言語設定と別に切替可能にする 🔶。
- **グラス表示**: §2の通りフォントのグリフ対応が言語ごとに異なるため、表示不可言語は **en もしくはローマ字へフォールバック**。レシピデータが `en` を必ず持つことで担保。
- **音声・認識**: STTコマンド辞書と材料 `aliases` を言語別に用意。バーコード商品名・写真AIの出力も選択言語へ正規化。
- **ユーザー自作レシピ**: 入力は単一言語でも可。`en` 未入力時は元言語を `en` キーにも複製し、フォールバックを成立させる（任意で機械翻訳補完 🔶）。

## 5. データモデル（ドラフト）

共通型は `packages/shared` に定義（スマホ/グラス/クラウドで共有）。

```ts
// 多言語テキスト: ロケール(BCP47)→文字列。最低 'en' を必須とし、未翻訳は fallback。
type Locale = 'ja' | 'en' | 'zh' | 'ko' | 'es' | 'fr' | string;
type LocalizedText = { en: string } & Partial<Record<Locale, string>>;

// 材料
interface Ingredient {
  id: string;
  name: LocalizedText;
  category: 'spirit' | 'liqueur' | 'mixer' | 'fruit' | 'bitters' | 'garnish' | 'other';
  aliases?: string[];           // 別名・表記ゆれ（検索/音声/認識用）
  isStaple?: boolean;           // 常備品（既定ON: 水/氷/砂糖など）
  substitutes?: string[];       // 代替候補の ingredient id
  barcodes?: string[];          // JAN/EAN（バーコード認識用）
}

// 在庫
interface InventoryItem {
  ingredientId: string;
  level: 'in' | 'low' | 'out'; // MVPは 'in' | 'out' でも可
  updatedAt: string;
}

// レシピ（カクテル）
interface Recipe {
  id: string;
  name: LocalizedText;
  glass: 'rocks' | 'highball' | 'cocktail' | 'collins' | 'shot' | 'wine' | string;
  method: 'build' | 'shake' | 'stir' | 'blend';
  ingredients: RecipeIngredient[];
  steps: LocalizedText[];
  tags?: string[];
  abv?: number;
  image?: string;
  source: 'builtin' | 'user';
}
interface RecipeIngredient {
  ingredientId: string;
  amount?: number; unit?: string; // 例: 45, 'ml'
  optional?: boolean;             // 任意（判定除外）
  garnish?: boolean;              // ガーニッシュ（判定除外）
}

// 判定結果
type MatchStatus =
  | 'makeable' | 'makeable_with_substitute'
  | 'missing_one' | 'missing_two' | 'unavailable';
interface MatchResult {
  recipe: Recipe;
  status: MatchStatus;
  missing: string[];                              // 不足 ingredient id
  substitutions: { required: string; used: string }[]; // 適用した代替
}

// Favorites / ピックアップ
interface Favorite { recipeId: string; addedAt: string; }
interface Pickup { id: string; type: 'inventory' | 'seasonal' | 'popular'; title: LocalizedText; recipeIds: string[]; }
```

## 6. アーキテクチャ / 技術スタック（提案）

モノレポ構成（pnpm workspaces 想定）🔶:

```
bartender/
├─ packages/
│  ├─ shared/      # 型・内蔵レシピDB(JSON)・判定エンジン・i18n辞書(多言語)
│  ├─ companion/   # スマホ コンパニオンWeb (Vite+React+Tailwind)
│  ├─ glass/       # G2アプリ (even-toolkit ブリッジ, screens)
│  └─ landing/     # 公開LP (静的/SSG) ※companion内ルートでも可
├─ docs/
└─ ...
```

| 層 | 技術（提案） |
|----|------|
| 言語/ビルド | TypeScript, Vite, pnpm workspaces |
| UI | React, Tailwind CSS |
| 状態管理 | Zustand（軽量）🔶 |
| ローカル保存 | IndexedDB（Dexie）/ localStorage |
| クラウド（任意） | Supabase（Auth / Postgres / Storage / Edge Functions） |
| バーコード | カメラ + `@zxing/library` 等。JAN→商品 解決は Open Food Facts 等の公開DB 🔶（対応範囲要検証） |
| 写真AI | Claude Vision（Edge Function 経由でAPIコール）🔶 |
| グラス | even-toolkit（`EvenHubBridge`, `useGlasses`, screen `{display, action}`） |

> 判定エンジンは `packages/shared` の純関数として実装し、ユニットテスト容易・スマホ/クラウド双方から再利用。
